# PanelIDE — Notes

## What it is

PanelIDE is a GTK3 project browser/editor and terminal workspace. Its project UI is independent of the executable hosted in the embedded **Harness** terminal. The shell uses a dark Graphite + Teal theme, keeps universal actions icon-only, labels PanelIDE-specific controls, and shows runner state with semantic color and text. File/folder icons continue to come from Material Icon Theme when available.

Launch from a checkout with `python3 panelide.py /path/to/project`, or use `panelide /path/to/project` after installing. See `README.md` for dependencies, configuration variables, and legacy-state migration.

## Current behavior

- Project tree updates through GFileMonitor, including nested folders.
- Text tabs autosave after 0.8 seconds; Ctrl+S saves immediately.
- CSV/TSV tables, images, PDFs, and audio use dedicated viewers.
- Each project tree has a local Git branch switcher next to New file/New folder. It lists local branches, marks the current one, and can create a branch from the current HEAD. Detached HEAD, an unborn repository (no commit yet), and uncommitted changes are surfaced in the button state/tooltip; an unborn branch is labeled `<name> · no commits` and its menu explains that the name is not a ref until the first commit. The tree reflects the real working tree: dotfiles are visible except VCS metadata, and entries are badged `untracked`, `ignored`, `mixed`, `empty`, `local`, or `repo` for a nested repository. Untracked/ignored counts are item counts from `git ls-files --directory`, so a wholly local folder counts as one item. After a successful switch the tree is rebuilt immediately instead of waiting for file-monitor events. Switching uses `git switch --no-overwrite-ignore` (falling back to `checkout`) so ignored and untracked files are not overwritten. Open editors pause autosave; clean buffers reload silently, dirty buffers whose file changed ask before keeping the editor version, and autosave resumes only for documents explicitly verified. Switch and create are reconciled alike, and every open file is re-stat'ed at decision time, so a worker snapshot is never trusted after the file changes. If verification or reading fails, the buffer is preserved, autosave stays suspended, the tab shows `⚠`, and a dialog offers keep-paused/reload/explicit-overwrite. The autosave callback itself never writes clean, conflicted, unsafe, or deleted documents, and it rechecks the disk immediately before writing. Ctrl+S uses the same disk check and asks before overwriting an unresolved conflict; only an explicit “Save local version” acknowledges the current disk snapshot. Ctrl+S on a deleted file opens a recovery dialog (recreate/save-as/cancel) instead of doing nothing. Recreate uses exclusive atomic creation and never overwrites a file that reappeared; new files keep the private 0600 mode from `mkstemp`, so a `.env` or credential file is not exposed even under a permissive umask. Save As enables GTK overwrite confirmation and then uses exclusive creation or a state-checked atomic replace, aborting if the target appears or changes during the save; overwriting an existing file preserves its mode, and a failed `chmod` leaves the target untouched. Branch snapshots, worktree classification, and the pre/post-switch digests run in background workers rather than on the GTK thread; opening the branch menu only performs cheap HEAD/local-ref queries (no working-tree walk). Worktree classification is cached for two seconds and forced after branch operations and for new/deleted entries; ignore-rule edits force it too.
- Known limits: worktree classification walks the repository index and the untracked/ignored lists, so badges can lag briefly behind a very large repository (the window stays responsive and repeated requests coalesce). A project opened through a symlink is rebased to the opened path, but a nested repository is only re-badged when its folder is expanded if it is a tracked submodule. A file literally named `.git` can be mistaken for repository metadata. Git can replace an empty folder when the target branch has a file at the same path (no file data is lost, but the folder itself is removed). External branch changes detected without a pre-switch digest rely on the saved mtime/size snapshot for dirty buffers; strict verification after PanelIDE's own switch/create deliberately pauses a dirty buffer when no pre-operation digest exists. An external rewrite that preserves both mtime and size can still evade the stat guard, although a decision-time content digest is required before a dirty buffer is resumed; that final digest runs on the GTK thread and is bounded by the editable-file size, so many dirty buffers can add a short pause. Closing a panel waits up to the Git switch timeout for an in-flight switch; if the operation finished but reconciliation did not run, or Git is still running, unsaved buffers are deliberately not written while Git may be rewriting the tree.
- Multitask view maintains independent project panels and can restore projects, open files, terminal counts, and collapsed-panel state.
- Runner controls inspect/manage configured GitHub Actions self-hosted runners; they are separate from the generic Harness terminal.
- `PANELIDE_HARNESS` selects the embedded executable. The old `MINI_IDE_OMP` setting and `omp` default remain for migration compatibility.
- The main header labels Open folder, Multitask, Session, and Files. Multitask project bars label Files and Terminal and keep runner state visible in a compact status badge.
- Visual rule: universal action → icon-only is OK. PanelIDE-specific action → icon + label. Important state → color + explicit text.
